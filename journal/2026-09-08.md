  bug: `git fetch origin ops-journal && git checkout ops-journal || git checkout --orphan
  ops-journal && git rm -rf --quiet . || true` chains `git rm -rf --quiet .` via `&&` to the
  *entire* preceding `||` expression (left-associative), not just the orphan fallback — so
  `git rm -rf` fires even after a normal, successful checkout, wiping the branch's working
  tree before every append. The `-f "$FILE"` check then always takes the overwrite branch,
  destroying prior entries. This has now happened twice (see commit `1a3a456`, itself a fix
  for the same clobber, and this run repeating it by following the template verbatim). Opened
  https://github.com/Holojerm/frontier-terminal/issues/11 proposing a fix (parenthesize the
  orphan fallback, or replace with an explicit `if`/`else` check) so routines stop hitting
  this.
