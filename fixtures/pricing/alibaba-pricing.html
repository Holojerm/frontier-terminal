    Alibaba Cloud Model Studio:Model Invocation Pricing

    Last Updated:Nov 18, 2026

    Model invocation uses the pay-as-you-go billing method by default, covering the billing rules and prices of various models.

    NoteThis page shows only the Original prices of model invocation. Go to the Model Studio console to view promotional offers.

    NoteSome models support context caching (Explicit Cache and implicit cache). Input tokens that hit the cache and tokens used to create an Explicit Cache are billed at unit prices different from standard input (for example, Explicit Cache creation is billed at 125% of the standard input unit price, and cache hits are billed at 10%). The input unit prices in the price tables of this page do not include cache prices. For the billing rules, unit price discounts, and supported models of caching, see Context cache.

    Tiered billing rules

    Some Model Studio models adopt tiered billing. The unit price depends on the total number of input tokens in a single request. All tokens of that request are billed at the unit price of the corresponding tier.

    In the billing ranges, K indicates 1,000 and M indicates 1,000,000. For example, 128K means 128,000 tokens, 256K means 256,000 tokens, and 1M means 1,000,000 tokens.

    For example, a model has two billing ranges: 0 < Token ≤ 32K and 32K < Token ≤ 128K. If the input is 100K tokens, since the value falls in the second range (32K < 100K ≤ 128K), all tokens are billed at the unit price of the second tier.

    Voice Chat

    Qwen-Audio-Realtime

    The realtime voice chat model supports text and audio input and output, and bills input tokens and output tokens separately. Audio tokens are converted based on duration: Total number of tokens = Audio duration (in seconds) * 12.5. Audio under 1 second is counted as 1 second.

    When only text is output, fees are charged at the text output unit price; when both text and audio are output, only the audio incurs output fees, and the accompanying text is not charged additional output fees.

    In multi-turn conversation scenarios, consistent with text LLMs, the model maintains the complete conversation context to preserve coherent conversation capability. Historical conversation content is processed and billed as input for subsequent turns, so the number of input tokens per turn grows gradually as the number of conversation turns increases. The specific billing methods for each type of content are as follows:

    • User input audio and text: Counted in the context and billed as input in each subsequent turn. Audio is billed as audio tokens, and text is billed as text tokens.
    • User-set instructions: Billed once per turn as text tokens.
    • Model output text: Counted in the context as text tokens and billed as input in each subsequent turn.
    • Model output audio: Billed as audio tokens only once at output, and not counted in the context.

    As the number of conversation turns increases, the number of tokens accumulated in the context grows gradually. We recommend that you reasonably control the number of turns per session or start a new session at an appropriate time to optimize usage costs.

    Token Consumption and Cost Control

    Billing method for reading files via URL: When reading files via URL, the file transfer process itself does not consume tokens. After the file content is parsed, it is converted into input tokens for billing, and the consumption depends on the length of the parsed text, not the file size. If you need to process large files, we recommend using knowledge base chunked indexing to reduce token consumption.

    How to troubleshoot abnormally high Credits consumption in a single request: Common causes include an excessively large input token count, enabling Agent mode (which incurs substantial overhead from system prompts, tool definitions, and thinking content), and so on. You can optimize costs by compressing the conversation history, starting a new conversation, disabling thinking mode, or switching to a lightweight model (such as the Flash series).

    Recommended models for low-frequency call scenarios: For low-frequency call scenarios such as heartbeat checks, we recommend using low-cost models such as the Qwen Flash series to reduce overall call costs.

    Note on decommissioned models: Decommissioned models such as the Qwen2.5 series are no longer available, and their prices cannot be queried. Please use newer models instead.
